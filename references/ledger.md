# 账本：两张表

**本文件是列定义的唯一事实来源。** `SKILL.md`、`scripts/` 下的所有脚本、其它 `references/` 文件都指向这里，不复制列定义。要改列，只改这一处。

---

## 为什么是两张表

一次调研会产生两类东西：

- **源**（source）：你抓到的每一个网页、论文、公告、财报。它有 URL、有类型、有可信度。
- **论点**（claim）：你要在报告里说的一句话结论。它引用若干个源。

deepdive 把它们塞进一张 13 列的表。我们拆成两张 10 列的表，原因是：

**那 3 列（来源类型、原始出处、发现路径）根本不是"论点"的属性，是"来源"的属性。** 一条论点引用 5 个源，就有 3×5＝15 个格子必须和 `sources` 列**按位置对齐**。这是模型会静默做错的那类活——数量对得上、内容错位、脚本还查不出来。拆开后，每个来源事实只写一次，写在它自己的行上。

拆完之后，`status`（这条论点站不站得住）**不再由模型手填，而是脚本从源表算出来的**。

## 表一：`sources.csv`（一源一行）

| 列 | 取值 | 填法 |
|---|---|---|
| `sid` | `01`–`99` 零填充两位数 | 抓取代理按分配到的区间取号。**报告里直接写 `[01]`，不做编号映射** |
| `url` | 原始 URL，完整 | 抓取代理 |
| `title` | 页面/文献标题 | 抓取代理 |
| `date` | 发布日期 `YYYY-MM-DD`；未知填 `unknown` | 抓取代理 |
| `type` | 严格 7 值：`一手` `学术` `行业媒体` `大众媒体` `专家博客` `论坛` `其他` | 抓取代理 |
| `credibility` | 整数 1–5。5＝一手/同行评议；4＝权威机构报告；3＝行业媒体；2＝大众媒体/博客；1＝论坛/匿名/AI 生成 | 抓取代理 |
| `access` | `full` `partial` `abstract` `closed` | 抓取代理，**如实填** |
| `root` | `own` ＝这就是原始出处；或短 id（`study-smith-2024`）＝它转述的上游；`unclear` ＝查不出来 | 抓取代理，**读源那一刻填** |
| `discovery_path` | `渠道\|确切查询词\|语言`，例如 `必应\|LNG接收站 投资\|zh` | 抓取代理，**必须是你实际用的词，不许复制粘贴** |
| `caveat` | `-` `vendor` `self-reported` `disputed:NN` | 严格枚举，**不许写自由文本** |

### 关于 `root` 和 `discovery_path`

这两列存在的唯一目的，是拆穿**假独立**：

- 三个链接其实是同一条新闻的转载 → 它们的 `root` 都是 `reuters-2025-03`，不是三个独立声音。
- 三个链接都是你用同一个搜索词搜出来的 → 它们的 `discovery_path` 一样，是**一条**发现路径，不是三条。

没有这两列，"三个来源"永远看着像三个来源。

**`root` 怎么算独立**（这条容易搞错）：

- `own` ＝这条源**本身就是原始出处**。它的出处身份是**它自己**。所以三个互相独立的一手源，`root` 都写 `own`，那是 **3 个**独立出处，不是 1 个。
- 短 id（`reuters-2025-03`）＝同一篇的转载。三个源写同一个 id，就是 **1 个**出处。
- `unclear` ＝查不出来源。保守地算作**同一个**未知出处——**证明不了的独立性不能算独立性**。想让它算数，就去把出处查出来。

### 关于 `caveat`

- `vendor`：卖方自己出的材料（设备厂白皮书、软件商案例）
- `self-reported`：自报数据（企业自称的产能、合格率）
- `disputed:NN`：有另一个源（编号 NN）公开质疑它

**严格枚举的意思是：写不出这四个值之一，就填 `-`。** 不许写"可能有偏向""需谨慎看待"这类自由文本——脚本读不了，人也不想读。

## 表二：`claims.csv`（一论点一行）

| 列 | 取值 | 填法 |
|---|---|---|
| `claim_id` | `CL1` `CL2`… 全文递增 | 主会话 |
| `claim` | 一句话命题。**不许含换行**；含逗号则整体加双引号 | 主会话 |
| `hypothesis` | `H1`–`H3` 或 `-`（对应 `research-plan.md` 里的假设） | 主会话 |
| `sources` | sid 列表，分号分隔：`01;07;12` | 主会话 |
| `status` | 严格 8 值，见下 | **脚本算，不是手填** |
| `confidence` | `high` `medium` `low` | 主会话 |
| `primary_source` | `Y` / `N`。判断标准：引用的源里有 `credibility=5` 的一手源，**且它真能托住这条论点** | 主会话 |
| `source_caveat` | `-` `vendor` `self-reported` `disputed:NN`。判断标准：**这条论点的关键数字锚**来自这类源 | 主会话 |
| `dissent` | 反对此论的 sid 列表，或 `-` | 主会话 |
| `as_of` | 关键数字的**数据日期**（`2025-Q3`）／`unknown`（有数无日期）／`-`（非数值论点） | 主会话 |

### 浅档例外

**浅档只要求 6 列**：`claim_id, claim, sources, status, confidence, as_of`。

缺列时：中档/深档 `ledger_check.py` 报错退出；浅档只给警告。这是为了防止一次轻量查询被流程压死。

## 四条件三角验证

一条论点算不算"被多方印证"，看它引用的源满足几个条件：

| # | 条件 | 含义 |
|---|---|---|
| 1 | `distinct(sources) ≥ 3` | 至少 3 个源 |
| 2 | `distinct(type) ≥ 2` | 至少 2 种来源类型（不能全是行业媒体） |
| 3 | `distinct(root) ≥ 2` | 至少 2 个原始出处（不能全是同一篇的转载） |
| 4 | `distinct(discovery_path) ≥ 2` | 至少 2 条独立发现路径（不能是同一个搜索词捞出来的一批） |

**四条全满足 → `triangulated`。**

### 什么源不计入这四条

以下源**不算数**，不进任何一个 `distinct`：

- `access` 是 `partial` / `abstract` / `closed` 的源（付费墙摘要页不算一个来源）
- 原文摘录少于 2 条的源

这条挡的是"抓到一个摘要页就凑一个来源"。

**「原文摘录」的判定约定**：`sources/NN_slug.md` 正文里**以 `> ` 开头的行**，每行算一条摘录。脚本就是数这个。所以摘录必须写成 Markdown 引用块，且**至少 2 行**——摘录要逐字、带段落定位，不许转述。

## 八个状态

`status` 由脚本按下面的顺序判定，**不是手填**：

| 值 | 什么时候 | 人话 |
|---|---|---|
| `triangulated` | 四条件全满足 | 四个维度都独立，站得住 |
| `contested` | `dissent` 非空，且异议源 `credibility ≥ 4` 或 `type=一手` | 有分量的反对意见没被消解 |
| `contradicted` | `dissent` 里的源直接推翻本论点 | 被证伪了 |
| `single-type` | 源够 3 个，但全是同一类型 | 三个都是行业媒体，等于一个 |
| `single-root` | 源够 3 个，但都转述同一个原始出处 | 三个链接，一个声音 |
| `single-path` | 源够 3 个，但都是同一条搜索路径挖出来的 | 独立性是假的 |
| `weak` | 源不足 3 个，或别的条件差得更多 | 证据太薄 |
| `data-insufficient` | 定向补挖 2 轮后仍然凑不齐 | 诚实地承认查不到 |

**`single-*` 三个值的区别很重要**：它们告诉你该往哪个方向补挖。`single-root` 要去找原始出处，`single-path` 要换搜索词或换渠道，`single-type` 要换来源类型（学术/官方/国际）。

## 两条硬规则

### 一、没有一手源，置信度不许超过 `medium`

`confidence=high` 只在 `primary_source=Y` 时允许。

理由：三个二手转述同一个原始事实，看着像"独立确认"，实际是一个声音被复读了三遍。这是深度调研最常见的幻觉来源。

### 二、矛盾不按多数决

`dissent` 非空且异议源有分量（`credibility ≥ 4` 或 `type=一手`）时，`status` 必须是 `contested`，**不许**因为"支持的一方源更多"就判 `triangulated`。

两方都要写进报告，并给出你选边的理由。不许用"更新的那个对"糊过去。

### 附：`source_caveat` 的影响

`source_caveat` 不是 `-` 时，`confidence` 必须 ≤ `medium`。是 `disputed:` 且没有仲裁结论时，必须 `low`。

理由：关键数字来自卖方自己的材料时，无论几个源复述，它还是卖方的话。

## CSV 书写硬规则

1. **`claim` 列不许含换行。** 需要换行说明它不是一个论点，拆成两条。
2. **含逗号则整体加双引号**，例如 `"投资回收期缩短，但前提是利用率超过 70%"`。
3. 分号 `;` 是列内分隔符，**正文里不要用分号**，用顿号或逗号。
4. 一律 UTF-8 编码。
5. 脚本一律用 Python 的 `csv` 模块读写，**绝不 `split(",")`**。

## 接合点：`outline.md`

账本到报告之间有一道最容易掉东西的缝：**一条已经成立的论点，写大纲时记得，成文时忘了**。`outline.md` 就是堵这条缝的：

- **章节标题用 `## ` 开头**（二级标题）。脚本按这个认章节。
- **每个章节下列出它支撑的论点编号**，例如 `- 支撑论点: CL1;CL4`。

脚本据此查三件事：

1. 每条 `triangulated` / `contested` 的论点，都要在大纲里出现
2. 大纲不许引用账本里没有的编号
3. **大纲里的每个章节标题，都要在 `report.md` 里出现**

第 3 条是重点。它不检查报告写得对不对，只检查「大纲里承诺的章节，报告里有没有」。少了就是成文时掉了内容。

> 注意：报告正文里写的是**源编号** `[01]`，不是论点编号 `CL1`。论点编号是内部账本用的，读者不需要看见。

## 手算核对清单（脚本不可用时的降级路径）

脚本跑不了时，对着这份清单人工核一遍，并在报告里注明「账本未经机器校验」：

- [ ] 两张表列名齐全（浅档 6 列，中/深档 10 列）
- [ ] `claims.sources` 里每个 sid 都能在 `sources.csv` 找到
- [ ] 没有重复 sid，没有同一 URL 登记成两个 sid
- [ ] `sources/NN_slug.md` 的编号都在分配区间内，没有越界
- [ ] 每条 `status=triangulated` 的，四条件逐条数一遍（**不是感觉够，是数够**）
- [ ] 每条 `confidence=high` 的，确认 `primary_source=Y`
- [ ] `source_caveat` 非空的，`confidence` 没有超过 `medium`
- [ ] `dissent` 非空且有分量的，`status` 写的是 `contested`
- [ ] `access` 是 `partial`/`abstract`/`closed` 的源，没有被算进四条件
- [ ] `outline.md` 里每个 `triangulated` / `contested` 的 claim_id，都在 `report.md` 里出现过
- [ ] 每条 claim 的 `sources` 个数和它引用的源个数对得上（防错位）
