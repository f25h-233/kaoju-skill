# 报告长什么样

## 核心区分：摆信息 vs 下判断

两种报告长得很像，但价值差一个数量级：

| | 摆信息 | 下判断 |
|---|---|---|
| 方法 | 搜多个来源 → 按主题分类 → 出清单 | 精读少数一手源 → 提炼张力 → 论证出判断 |
| 结构 | 主题分类：市场 / 竞争 / 趋势 | 论证链：观察 → 分析 → 判断 → 局限 |
| 产出 | 「A 做了 X，B 做了 Y」 | 「A 和 B 从相反前提出发却收敛了，为什么」 |
| 深度来自 | 覆盖了多少角度 | 用哪个框架在看 |
| 读起来像 | 排版整齐的维基词条 | 真动过脑子的人写的备忘录 |

**默认状态是左边那种**——它更容易写、看起来更全、也更容易骗过自己。这份文件是一套护栏，把它拽到右边。

## 章节标题检测器

写完之后，看一遍所有二级标题，问：

> **这些标题能不能直接拿去当搜索关键词？**

能，就说明结构是**信息分类**而不是**论证链**。

- ✗ 坏的：「定价对比」「功能对比」「适合谁」「市场现状」
- ✓ 好的：「能力趋同之后，竞争的新维度是什么」「为什么两家从相反前提得出了同一个结论」

**好标题里包含判断。** 分类标题里只有名词。

---

## 表格和 bullet 的禁令

> **删掉所有表格和 bullet point 之后，剩下的段落能不能独立成文？**

不能，就说明思考量不够，表格在替代思考。

规则：
- 报告正文的段落占比应 **≥80%**
- 表格只用于**并列的事实数据**（参数对比、时间线），不用于**承载论证**
- 一个洞见如果能塞进表格，它大概率不是洞见

## 结构

```
# 标题

## 摘要（200–400 字）
  结论是什么、凭什么、最大的不确定性在哪。只写这三件事。

## 一、（包含判断的标题）
  论证：观察 → 分析 → 判断。每章只推进一个论点。

## 二、…

## 局限与代价
  这次没查到什么、哪条结论最脆、如果错了会错在哪。

## 本次缩减了什么
  熔断停下时写明停了哪一步。没触发熔断就写「无」。

## 参考文献
  [01] 标题 | URL
  [02] …
```

## 七条自检

交稿前逐条过一遍：

1. **删表格测试**：删掉所有表格和 bullet，剩余段落能否独立成文？
2. **标题测试**：章节标题能直接当搜索关键词吗？能就是分类不是论证。
3. **反驳测试**：核心结论发到相关领域的专业群里，**会有人出来反驳吗**？没人反驳就是太安全了。
4. **三句话测试**：如果整篇报告的核心论点三句话就能说完，那它不该是一万字。
5. **出处测试**：每个非显然的论断都有行内引用 `[NN]` 吗？
6. **口径测试**：每个数字都标了 `as_of` 数据日期吗？（有数无日期写 `unknown`）
7. **不确定测试**：查不到的地方，是诚实写了「未查到」，还是用推测填了？

第 7 条最容易被违反，也最致命。

---

## 摘要怎么写

只写三件事，不要多：

1. **结论是什么**（一句话，包含判断）
2. **凭什么**（最硬的那两三条证据）
3. **最大的不确定性在哪**（哪条最脆、什么情况下会翻转）

不要写「本文将从以下几个方面展开」这类导航句。读者要看的是结论，不是目录。
