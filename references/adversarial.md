# 红队

## 先说清楚红队能干什么、不能干什么

**本机的所有子代理跑的是同一个模型。** 所以五个角色不是五个独立的大脑，是同一个大脑被要求从五个角度看。它们的**共同盲区不会被消除**。

因此：

- 红队的作用是**补漏**（找出你忘了检查的地方），**不是证伪**（它证明不了你的结论是对的）
- 关键结论的可靠性来自**跨来源三角验证**（不同来源、不同渠道、不同语言），不是来自红队
- **不要为了「更独立」而多开代理**——多开只增加成本，不增加独立性

这条写在这里，是为了防止把红队的输出当成质量保证。

---

## 五个角色

| 角色 | 它问什么 |
|---|---|
| **怀疑的实践者** | 这条结论落到真实场景里会怎样？谁会按它做决定，然后被坑在哪？ |
| **对抗性审稿人** | 推理链哪一步是跳过去的？哪个「因此」其实接不上？哪条证据被当成了它撑不住的东西？ |
| **落地工程师** | 要执行这条结论，第一步卡在哪？前置条件是什么？谁负责？ |
| **少数派辩护人** | 被压掉的那个异议，如果它是对的呢？它的最强版本是什么？ |
| **数字审计员** | 每个关键数字的出处、口径、时点是什么？两个数字能不能直接比？ |

**为什么「少数派辩护人」要独立成一个角色**：调研里会出两种方向相反的认知失效——一种是**过早收敛**（急于下结论，忽略反证），一种是**拒绝收敛**（什么都说不清，永远在补证据）。这两种毛病塞进同一个角色里会互相抵消，两个都做不好。所以分开。

---

## 严重度只有三档

**HIGH / MEDIUM / LOW。**

**不要用 1–5 分打分。** 理由：模型当评委时有系统性偏置——偏爱更长的输出、偏爱排在前面或后面的选项、偏爱自己写的答案。分数会显得很精确，但那个精确是假的。三档结构判定反而更诚实。

| 档 | 判据 | 处理 |
|---|---|---|
| **HIGH** | 结论可能因此翻转；或引用的源撑不住这个论断 | 必须闭环：补证据、改结论，或显式写明「此处存疑，原因是…」 |
| **MEDIUM** | 削弱但不推翻 | 在「局限与代价」里写明 |
| **LOW** | 表述问题、可读性 | 随手改 |

**每个 HIGH 都必须有交代**，不许留着一个 HIGH 直接交稿。

---

## 深度闸门

| 档位 | 跑哪几个角色 |
|---|---|
| 浅 | 不跑红队 |
| 中 | 怀疑的实践者 + 对抗性审稿人 |
| 深 | 全部五个 |

浅档不跑红队不是偷懒——浅档的结论本来就只是初步判断，不该被当成决策依据。

---

## 找反例的检索配方

专门补一轮反面检索，关键词加这些词：

`criticism` / `failure` / `problem` / `why not` / `limitation` / `drawback`

中文对应：`问题` / `失败案例` / `为什么不` / `缺点` / `质疑` / `翻车`

**如果一轮反面检索什么都没找到**，先怀疑检索方式，再怀疑「真的没有反例」。通常是真的没找对地方。

---

## 分工：谁做红队

**主会话自己起角色，不派代理。**

理由还是开头那条——派出去的代理和你是同一个模型，多一层调用不会让它更独立，只会让你看不到它的推理过程。

---

## 输出格式

`redteam/<日期>_roles.md`：

```
## 怀疑的实践者
- [HIGH] 结论里假设了利用率会维持在七成，但没有证据支持这个假设长期成立。
  → 处理：已在「局限与代价」写明该假设是结论成立的前提。

## 对抗性审稿人
- [MEDIUM] 第二段的「因此」跳过了中间一步。
  → 处理：补了一句过渡。
```

每条必须带**处理结果**。只列问题不给处理的，等于没做。
