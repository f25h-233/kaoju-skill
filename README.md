# 考据 · 深度调研 skill

> 把「我觉得」变成「有账可查」。

一个 Claude Code skill：把一个问题挖成一份**有账本、可核验、敢下判断**的中文报告。

**English**: [README.en.md](README.en.md) —— 机器翻译版

---

## 它解决什么问题

市面上的「AI 深度调研」绝大多数产出的是**摆信息**，不是**下判断**：

| | 摆信息（默认状态） | 下判断（本 skill） |
|---|---|---|
| 方法 | 搜多个来源 → 按主题分类 → 出清单 | 精读少数一手源 → 提炼张力 → 论证出判断 |
| 产出 | 「A 做了 X，B 做了 Y」 | 「A 和 B 从相反前提出发却收敛了，为什么」 |
| 读起来像 | 排版整齐的维基词条 | 真动过脑子的人写的备忘录 |

摆信息更容易写、看起来更全、也更容易骗过自己。这个 skill 是一套护栏，把它拽到另一边。

---

## 核心：两张表 + 四条件

一次调研产生两类东西——**来源**和**论点**。本 skill 要求它们分别记进两张表：

- `sources.csv`：每个源一行（URL、类型、可信度、原始出处、发现路径…）
- `claims.csv`：每条结论一行（引用了哪些源、置信度、有没有异议…）

然后**每条结论都要过四条件三角验证**：

> **≥3 个独立来源、≥2 种来源类型、≥2 个原始出处、≥2 条独立发现路径**

四条全满足才算成立。**关键是 `status` 不由模型手填，由脚本从源表算出来**——手填的值和源表对不上，校验直接判失败。

两条硬规则：

1. **没有一手源，置信度不许超过 `medium`。** 三个二手转述同一个原始事实，看着像独立确认，实际是一个声音被复读三遍。
2. **矛盾不按多数决。** 有分量的反对意见出现时，不许因为「支持的一方源更多」就判它成立。

## 用法

直接说人话就行：

```
帮我深挖一下 LNG 接收站的投资逻辑
考据一下 Postgres 逻辑复制和 CDC 工具的取舍
写一份调研报告：这个技术选型值不值得
```

触发词：考据、深挖、深度调研、调研报告、挖到底、刨根问底、值不值得。

**不适用**：一次搜索能答完的事实查询、总结你已给的单篇材料、纯头脑风暴、只要一段话的短答。

## 校验脚本

```bash
python scripts/check_all.py --workspace <工作目录> --depth medium
```

一条命令跑完账本校验、引用校验、源质量、摘要生成。退出码 `0` = 通过，`1` = 有步骤失败。

**脚本全部纯 Python 标准库，零第三方依赖，Windows 直接能跑。**

**脚本是可选的**：删掉 `scripts/` 流程照样走，只是校验降级成人工自检——但报告里必须写一行「降级模式：未做机器校验」。

### 脚本能做什么、不能做什么

| 能 | 不能 |
|---|---|
| 查出账本自相矛盾（声明 triangulated 但源表算不出） | 判断结论对不对 |
| 查出置信度超天花板、异议被压掉 | 验证引文内容真实 |
| 查出引用悬空、大纲漏章节 | 证明你真的读过那个源 |

**脚本通过 ≠ 结论可靠。** 结论可靠性靠跨来源三角验证和红队，不靠脚本。

## 三个设计取舍

**一、13 列账本拆成两张 10 列的表。**
来源类型、原始出处、发现路径这三列不是「论点」的属性，是「来源」的属性。留在论点表里，一条结论引 5 个源就有 15 个单元格要做位置对齐——这是模型会静默做错、脚本还查不出来的活。拆开后每个事实只写一次。

**二、全面落盘，不做「只交终稿」。**
中间结果全部写盘。这不是洁癖：本机自动压缩关闭，长调研不会优雅降级而是直接撞墙，没落盘的东西等于已经丢了。

**三、红队定位为补漏，不是证伪。**
本机所有子代理跑同一个模型，五个角色不是五个独立大脑，共同盲区不会被消除。所以关键结论的可靠性来自跨来源三角验证，不来自红队；也**不要为了「更独立」而多开代理**——多开只增加成本，不增加独立性。

## 已知不足

见 [ROADMAP.md](ROADMAP.md)。里面记录了**红队强度不足**的完整诊断（三条病因、哪条已修、哪条待办），以及每条待办的改法、代价和**为什么现在不做**。

一句话版本：红队不够红的根因不是角色少，是**所有子代理跑同一个模型**——加角色等于让同一个人多戴一顶帽子。所以待办方向是**改任务形态**（从「检查」到「重构利益结构 + 生成反方论证」），不是加角色。
